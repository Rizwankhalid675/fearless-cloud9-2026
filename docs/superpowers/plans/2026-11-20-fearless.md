# Fearless Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Fearless Draft organiser for League of Legends coaches in which a deterministic rules engine owns champion availability, and no suggestion an advisor makes can reach the screen as pickable unless that engine says it is legal.

**Architecture:** A pure TypeScript rules engine derives the legal champion pool from series state and owns the draft-order state machine; it has no UI, network or clock dependency, so it is exhaustively testable. An advisor (offline heuristic by default, optional LLM) proposes picks and bans; every proposal passes through `gateSuggestions` before rendering, and an illegal one is displayed as blocked with the reason and the game the champion was burned in. A React/Vite front end renders the draft board. State lives in the URL-independent series object, exportable to a file and reimportable, so a dead laptop between games costs nothing.

**Tech Stack:** TypeScript, Vite, React, Vitest, Riot Data Dragon (vendored snapshot), GitHub Pages. Built in WebStorm; `.idea/` committed.

**Spec:** `docs/EVENT.md` (§5 category, §7 submission checklist, §8 judging, §9 the project)

## Review Focus

Five things the spec implies, that no obvious task tests, most likely to bite first:

1. **A champion picked in game 1 by Blue and also hovered by Red in game 3** — the pool must stay correct regardless of which side burned it; the blocked reason must name the right game and the right team. Tested in Task 3.
2. **Ruleset variance between leagues.** "Fearless" is not one rule: in the common variant previous *picks* are burned for both teams; in "team fearless" only for the team that picked them; bans never carry. Guessing one and hard-coding it makes the tool wrong for half its users. Both variants are configurable and pinned by tests in Task 3.
3. **A series imported from a file written by an older version** — an unknown or renamed champion id must not crash the board; it must be surfaced as an explicit, named problem. Tested in Task 6.
4. **The advisor returning a champion that does not exist** (an LLM hallucinating "Mordekaisor"). This must be blocked by the same gate as an illegal pick and shown with a distinct reason, not silently dropped. Tested in Task 7.
5. **A draft where every remaining legal champion for a role is exhausted** — by game 5 with 40 burned champions this is reachable; the board must say so rather than render an empty list. Tested in Task 4.
